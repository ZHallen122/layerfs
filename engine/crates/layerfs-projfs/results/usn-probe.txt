# What this shows:
# - A reason is added to a file's record once between two closes, and the close is the last
#   handle's: while the reader held the files, ProjFS's write-in of the content was not closed.
# - The overwrite in place added no record at all: "overwrite" was in the record already. Until
#   the last handle closed, the journal held nothing that tells the overwritten file from one that
#   was only read. The close record then shows the file without the reparse attribute.
# - So a file with a data reason and no close has to stay suspect, whatever wrote the reason.
